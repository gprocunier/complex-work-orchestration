Complex Work Orchestration

A Codex skill for turning large, risky, or multi-session work into a controlled Mixture of Experts operating model with durable handoffs.

What This Does

complex-work-orchestration is for projects that are too large, stateful, or coordination-heavy for a single chat thread. It helps structure multi-session work, parallel investigations, contractor handoffs, lab or release work, and tasks that need durable tracking.

Mixture Of Experts Model

The skill separates responsibilities into explicit roles so agents do not all improvise on the whole project. Each expert gets a defined lane, scope, expected output, validation requirement, and escalation rule.

Architect Owns decomposition, technical judgment, integration, acceptance, and final decisions.
Project Manager Keeps the work graph clean, tracks dependencies, status, assignments, blockers, and handoffs.
Workerbees Handle bounded implementation, research, test triage, validation, and evidence gathering.
Outside Contractor Claude or another LLM/agent that receives a narrow assignment and reports back through the agreed handoff path.

Outside Contracting

Outside agents are treated like contractors, not project owners. They receive one explicit task at a time, usually backed by a Beads issue. Each contract carries a job-description label such as contract-jd-general-reasoning, contract-jd-security-reasoning, or contract-jd-architecture-reasoning so the outside model knows which reasoning lens it is being hired to apply. The contractor receives interaction.html as the briefing document plus the specific assignment.

A contractor assignment should include:

  • purpose and scope
  • job-description label and discipline lens
  • allowed files or areas
  • things not to touch
  • expected deliverable
  • validation required
  • escalation triggers
  • handoff format

Contractors should not re-plan the project, close parent epics, publish releases, touch secrets, or run destructive commands. Their job is to return focused work, evidence, alternatives considered, risks, confidence, and blockers.

Durable Coordination

When Beads is available, the skill uses bd as the shared work graph: epics, tasks, dependencies, comments, status, and ready work. When Beads is not installed, the skill still works using Markdown handoff state, with less durability.

Documentation

How It Gets Invoked

Invoke it explicitly with:

Use $complex-work-orchestration to scaffold this project.

It should also trigger naturally when a request mentions Mixture of Experts, project manager, workerbees, Claude contractor handoff, Beads work graph, durable handoff, or complex multi-agent work.
