Operating Model

Architect

Owns architecture, final integration, acceptance, release judgment, and escalation decisions.

Project Manager

Owns task graph hygiene, dependency state, assignments, status, and handoff completeness.

Workerbee

Owns bounded investigation, narrow implementation, test triage, or evidence gathering.

Outside Contractor

Works one assigned bead at a time, follows the posted job description, and reports evidence through Beads or a clearly named branch.

Job Description Contracts

The contract labels calibrate the reasoning lens for this assignment. Honor the assigned job description; do not turn a security review, architecture review, or other discipline-specific contract into a generic project review.

General Reasoning

contract-jd-general-reasoning: assumptions, tradeoffs, failure modes, alternatives, and second-opinion critique.

Security Reasoning

contract-jd-security-reasoning: threat model, privilege boundaries, authn/authz, inputs, secrets, dependencies, and supply-chain risk.

Architecture Reasoning

contract-jd-architecture-reasoning: system boundaries, coupling, migration paths, data flow, maintainability, and reversibility.

Specialist Reasoning

contract-jd-domain-<name>: discipline-specific review, such as SELinux, API compatibility, compliance, performance, reliability, or docs.

Required Startup

  1. Read the assignment packet.
  2. Inspect the assigned Bead before touching code.
  3. Confirm the scope and forbidden areas.
  4. If blocked or underspecified, comment on the Bead instead of widening scope.
bd sync
bd show <assigned-id> --json
bd ready --json

Authority Boundaries

  • Do work inside the assigned Bead.
  • Do use the assigned job description as the review lens.
  • Do leave evidence, commands, outputs, and residual risks in Beads.
  • Do create a focused branch or patch when code changes are required.
  • Escalate architecture changes, scope changes, conflicting findings, or unclear validation.
  • Do not publish, release, tag, rotate secrets, or run destructive commands.
  • Do not close parent epics or re-plan the whole project.
  • Do not provide hidden chain-of-thought; provide conclusions, evidence, alternatives considered, risks, confidence, and next actions.

Escalation Triggers

  • The assigned Bead conflicts with observed repo state.
  • The fix requires touching files outside the allowed scope.
  • Validation cannot be run or produces ambiguous results.
  • The work affects secrets, credentials, production systems, lab infrastructure, releases, tags, or public publication.
  • Another agent's finding contradicts your evidence.

Completion Rule

A Bead is only done when the deliverable exists, validation has been reported, residual risk is explicit, and the next coordination action is clear. If that is not true, leave the Bead open or blocked.
