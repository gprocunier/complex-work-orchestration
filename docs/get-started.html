Install the Skill

A Codex skill is a local instruction pack that Codex can load during a conversation. Install CWO into your Codex skills directory, then invoke it from the Codex prompt.

Clone the repository and run the guided installer. It detects a Codex skills directory from CODEX_SKILLS_DIR, CODEX_HOME, or $HOME/.codex/skills, then prompts before copying files. 

git clone https://github.com/gprocunier/complex-work-orchestration.git
cd complex-work-orchestration
./scripts/install.sh

For unattended installs, pass the destination explicitly: 

./scripts/install.sh --skills-dir /path/to/codex/skills --yes

The installer verifies the copied skill with a source-vs-installed content manifest and writes .cwo-install-manifest.json inside the installed skill. Check an existing install without modifying it: 

python3 scripts/check_installed_skill.py --check

If the checker reports missing or drift, rerun the installer against the same Codex skills directory to reload the skill.

Beads is required for the durable workflow. The skill installer only warns when bd is missing so the documentation can still be installed and read. 

command -v bd
bd version

On Fedora, RHEL, or compatible systems, use your own Beads package source if you have one. If you need a public example, the installer points at the greg-at-redhat/beads COPR. Set BEADS_COPR=owner/project before running the installer to show a different COPR hint. 

sudo dnf copr enable greg-at-redhat/beads
sudo dnf install beads

For non-RPM systems, use an upstream-supported Beads install channel such as Homebrew on macOS or Linux, or the quick install script for macOS, Linux, or FreeBSD. 

brew install beads
curl -fsSL https://raw.githubusercontent.com/gastownhall/beads/main/scripts/install.sh | bash
bd version

For the current Beads installation matrix, use the upstream Beads project at github.com/gastownhall/beads.

Start The Candidate E Baseline

Candidate E is CWO's default instruction profile for the Codex session that owns scope, integration, acceptance, and handoff. Install and verify its named profile after the skill is in place: 

python3 scripts/manage_instruction_profile.py install --profile operator-e
python3 scripts/manage_instruction_profile.py verify --profile operator-e

The profile manager writes a hash-bound prompt under $CODEX_HOME and installs the cwo-codex launcher under ~/.local/bin by default. It does not edit the global Codex configuration or change ordinary sessions.

Start a fresh CWO session from the target project:

cwo-codex -C "$PWD"

If the launcher directory is not on PATH, use:

codex --profile cwo-sol-operator-e -C "$PWD"
Fresh session required: Resuming an older thread does not activate the named profile or provide profile-selection evidence. If a fresh process is unavailable, explicitly reading and following the Candidate E prompt is a supported fallback for that thread, not equivalent profile activation. The word profile here means the operator instruction contract; Connected Codex, OpenCode, and local endpoints are execution environments selected later.

Candidate C remains an opt-in compatibility alternative. Start a fresh ordinary codex -C "$PWD" session for immediate rollback. Exact profile removal is in Reference.

Choose Your Starting Path

Connected Codex

Use Candidate E and keep focused work in its session, adding one supervised Spark worker only when delegation helps.

Review Needed

Let the coach add bounded review lanes. Reviewer output stays evidence until the evaluator and Candidate E accept it.

Restricted Or Airgapped

Select the matching execution environment before dispatch. These paths use their own approved shell and model profiles.

Run the Coach

In the fresh Candidate E session, ask the coach to size the work. Codex can run the local helper, show the recommended level, and ask any interactive questions before execution starts. If you are already in an OpenCode or manual shell profile, run the helper directly and choose that execution profile before dispatch. 

/plan Use $complex-work-orchestration prompt coach:
Clean up installer docs, tests, and handoff notes.

The simple path is five steps: ask for the coach, answer any execution-changing choices, create or update one Beads task, validate the work, and close the task with enough context for a later session to pick up where you left off. The simple use case shows that sequence without the full contractor workflow.

Codex may run this helper behind the scenes. Use direct script execution only for automation, CI, troubleshooting, OpenCode, or an operator shell outside Codex.

Operator Reference: Coach Helper 
python3 scripts/coach_prompt.py \
  "Clean up installer docs, tests, and handoff notes."
Default posture: The skill always expects durable Beads tracking. Narrow work can stay in the current thread, but it should still leave one Beads task with evidence and validation notes.

Core Terms

Learn these terms for the first run. The expert vocabulary lives in Reference.

CWO

Complex Work Orchestration: the workflow that sizes, records, reviews, validates, and hands off complex agent work.

Candidate E

CWO's default instruction profile. Its session owns scope, integration, acceptance, and handoff.

Prompt Coach

Sizes a request before execution so Codex uses the right amount of tracking, review, and validation.

Beads

The durable task graph for scope, dependencies, evidence, validation, closure memory, and handoff.

Validation

The checks that prove the work is ready, such as tests, docs validation, install smoke, or Pages deployment.

Native Supervision

The local supervisor outside the worker verifies, binds, and monitors a fresh Spark session for a narrow implementation or validation task.

Closure Memory

The final Beads comment that explains what happened, how it was checked, and what a future agent should know.

Record Beads

Use Beads as the shared work story. If the repository should own the durable state, initialize it once. If a Dolt remote is configured, pull before handoff work and commit or push after recording evidence. Without a remote, the graph is durable local state on this machine but not shared across machines.

Operator Reference: Beads Checks 
command -v bd
test -d .beads && bd ready --json || true
bd init
bd dolt remote list
bd dolt pull
bd dolt commit
bd dolt push

If Beads is unavailable or cannot be installed, record the same task or graph structure in a temporary Markdown plan file and note that durability is reduced. The full workflow and fallback limits are covered in Workflows.

When the work closes, the useful memory should be in the final comment, not the terse close reason. Capture who was involved, what changed, why it closed, how it was validated, when it closed, where it ran, any residual risk, and follow-up.

Operator Reference: Closure Comment 
bd comment "$BEAD_ID" --body "$(cat <<'EOF'
Closure memory:
- Who: Codex main thread; reviewer lane if applicable.
- What: Changed docs, validation, or handoff artifact.
- Why: Accepted and ready to close.
- How: Validation command, CI run, install smoke, or review evidence.
- Where: Repository, branch, and Beads local-only or Dolt-backed mode.
- Residual risk: None known, or the exact remaining risk.
EOF
)"

Generated Beads populate native fields for skills, acceptance, design, and notes. The description remains the readable assignment body. When creating Beads manually, use real newlines through a heredoc, --body-file, --design-file, or command substitution instead of typing literal \n sequences.

Worker-facing ready work should exclude contractor and local worker guard labels:

Operator Reference: Ready Work Filter 
bd ready \
  --exclude-label contractor-only \
  --exclude-label local-worker-only \
  --exclude-label no-codex-exec \
  --json

Execute Safely

Let the coach decide whether the work stays in the current conversation, becomes a lightweight Beads task, or needs a larger work graph. Candidate E remains the decision owner. If work is delegated in connected Codex, one supervised native Spark worker is the standard path. Outside reviewers, local workers, and concurrent pools are separate optional paths.

  1. Install and verify Candidate E, then start a fresh cwo-codex session.
  2. Invoke the skill when sizing is unclear, or run the helper directly from another approved execution environment.
  3. Let CWO route non-trivial work against the policy.
  4. Create a Beads task, or an epic when the goal has several dependent parts.
  5. Run validation before accepting findings or publishing.

Continue with Workflows for the end-to-end path or Native Supervision for the worker control and failure model.
