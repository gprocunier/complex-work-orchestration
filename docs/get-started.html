Check your starting point

A terminal runs commands on your computer. Codex is the project agent you will use; CWO adds the work record and operating instructions. This walkthrough uses Linux, Python 3, Git, a working authenticated Codex CLI, and Beads for saved tasks.

Already have those tools? Run this check, then go straight to installation.

Terminal

python3 --version
git --version
codex --version
bd version

Command check: all four print versions. That checks availability, not authentication or a working database. Before installing CWO, confirm an ordinary Codex session can start with your account. The practice-project Beads backend is checked with bd ready --json after initialization in step 3. A missing command is a setup step to finish, not a tutorial failure.

If a prerequisite is missing

  1. Start with your Linux terminal. Use your distribution’s package instructions for Python 3 and Git, then reopen the terminal and repeat their version checks.
  2. Set up Codex next. Follow the official Codex CLI installation and sign-in instructions. You perform account sign-in yourself; never put credentials in a project prompt. Return when codex --version works and you can start an authenticated session.
  3. Add task storage. Follow the maintained Beads installation instructions, including the backend setup required by your version. Return when bd version works. You will initialize the separate practice project in step 3.

Codex uses your model account and its quota; CWO does not supply model access. Beads can need a local database service. No contractor account or local-model server is needed for this exercise.

Already have Codex and want help checking the rest?

Prompt inside Codex

Check whether Python 3, Git, Codex CLI, and Beads are available. Explain missing prerequisites using their official instructions. Do not install packages, change global settings, authenticate for me, or bypass permissions.

Your first project, in four stages

  1. Install CWO and verify its named profile.
  2. Repair the checker and inspect its saved decision.
  3. Continue in a fresh session to add the CLI.

The result is a local utility, passing tests, and a handoff you can inspect.
