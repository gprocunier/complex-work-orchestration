Get Started

Install the skill, let the prompt coach size the work, and create the first durable Beads record before execution starts.

Install

Clone the repository and run the guided installer. It detects a Codex skills directory from CODEX_SKILLS_DIR, CODEX_HOME, or $HOME/.codex/skills, then prompts before copying files. 

git clone https://github.com/gprocunier/complex-work-orchestration.git
cd complex-work-orchestration
./scripts/install.sh

For unattended installs, pass the destination explicitly: 

./scripts/install.sh --skills-dir /path/to/codex/skills --yes

Beads is required for the durable workflow. The skill installer only warns when bd is missing so the documentation can still be installed and read. 

command -v bd
bd version

On Fedora, RHEL, or compatible systems, use your own Beads package source if you have one. Otherwise the installer points at the public greg-at-redhat/beads COPR. Set BEADS_COPR=owner/project before running the installer to show a different COPR hint. 

sudo dnf copr enable greg-at-redhat/beads
sudo dnf install beads

For other platforms, use the upstream Beads project at github.com/steveyegge/beads.

Run the Coach

In Codex, start with the prompt coach when the right amount of orchestration is unclear. Codex can run the local helper, show the recommended level, and ask any interactive questions before execution starts. 

/plan Use $complex-work-orchestration prompt coach:
Clean up installer docs, tests, and handoff notes.

Codex may run this helper behind the scenes. Use direct script execution only for automation, CI, troubleshooting, or an operator shell outside Codex. 

python3 scripts/coach_prompt.py \
  "Clean up installer docs, tests, and handoff notes."
Default posture: The skill always expects durable Beads tracking. Narrow work can stay in the current thread, but it should still leave one Beads task with evidence and validation notes.

Record Beads

Use Beads as the shared work story. If the repository should own the durable state, initialize it once. If a Dolt remote is configured, pull before handoff work and commit or push after recording evidence. Without a remote, the graph is durable local state but not shared across machines. 

command -v bd
test -d .beads && bd ready --json || true
bd init
bd dolt remote list
bd dolt pull
bd dolt commit
bd dolt push

Generated Beads populate native fields for skills, acceptance, design, and notes. The description remains the readable assignment body. When creating Beads manually, use real newlines through a heredoc, --body-file, --design-file, or command substitution instead of typing literal \n sequences.

Worker-facing ready work should exclude contractor and local worker guard labels: 

bd ready \
  --exclude-label contractor-only \
  --exclude-label local-worker-only \
  --exclude-label no-codex-exec \
  --json

Execute Safely

Let the coach decide whether the work stays in-thread, becomes a lightweight Beads task, or needs full architect/PM/internal worker workstreams. Outside contractors and local workers are optional workstreams selected later; they are not the starting point.

  1. Invoke the skill from Codex when sizing is unclear.
  2. Let Codex route non-trivial work against the policy.
  3. Create a Beads task or epic with dependencies.
  4. Run validation before accepting findings or publishing.
