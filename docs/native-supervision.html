Delegation is a controlled operation

If CWO delegates native work, the assignment is bounded and supervised. There is no unsupervised native-worker opt-out. A small explicitly authorized maintenance task can stay in its main thread; delegation is not a prerequisite for getting value from durable records.

Do not read this overview as a dispatch grant. Use the active policy and an admitted runtime with actual model, tools, workspace, qualification, ownership and budget evidence.

Current routing: size the task, then qualify the exact worker

The active task_selected_routing v3 policy selects gpt-5.6-luna first after model-neutral sizing. gpt-5.6-terra is escalation-only for documented fit, qualification, risk or economics reasons. Spark and GPT-5.5 v2 records are historical, not new dispatch authority.

Each current attempt needs exact requested/observed identity, source/context/scope and budget bindings, qualification, precommit and release evidence. A model name accepted by a CLI or a passed tool-surface probe does not prove a productive route is qualified. Do not substitute another available model silently.

The normal single-worker path

  1. Close acceptance and scope in a durable task; estimate the complete work before model selection.
  2. Establish exact model/tool/host qualification and present ownership. Check enforced filesystem/network boundaries, not just an instruction to be read-only.
  3. Bind the fresh attempt, precommit, packet, release and finite operation reservation.
  4. Register persistence and observers before triggering work. Use the admitted transaction and supervised lifecycle.
  5. Validate product behavior and final mutation attribution, close owned resources, evaluate the return and record the owner's acceptance decision.

Transport completion, a worker's success Boolean, or import success is not product acceptance. A realignment return is nonaccepted. Stopped sessions stay terminal; a new attempt requires a distinct fresh allowance.

Optional concurrency is a preview

Supported fixed cohorts are N=1..3 only where actual compatible host capability, admission, workspace ownership, leases and aggregate capacity are established. A flag is not proof. Keep Beads, journals, reducers, promotion, model dispatch and other stateful operations serial as their contracts require.

Pool contracts, admission, interruption and cleanup preserve the details and historical evidence. Read-only semantic work still needs an actually enforced read-only boundary and zero consistent mutation claims.

Recover at the affected scope

After a failure, establish containment, ownership, consumed allowance, dependencies and remaining authority before deciding whether the parent must stop. Preserve failures and UNKNOWN findings. Continue independent ready work only when its own gates pass; dependent work remains blocked until its prerequisite is accepted.

Explicit self-maintenance uses a separately adopted mission with owner-issued in-process capabilities and bounded operations. A serialized authority snapshot is not a grant; do not turn maintenance machinery into ordinary onboarding.

Historical contracts stay inspectable

The source references retain Spark/v2 packets, fallback semantics and qualification records for interpretation and migration. Their present-tense historical command examples are not current instructions for new dispatch. The current overview and active v3 policy take precedence for selecting a fresh worker; they do not rewrite old evidence.
