Beads Memory

Beads gives long AI coding work a durable project memory. It records scope, dependencies, evidence, decisions, validation, and closure-memory comments outside the fragile chat transcript.

Why It Matters

Web-chat work often lives inside one long conversation. That is fine until the task spans days, the context window fills, the session is summarized, or another agent starts without the original transcript. CWO uses Beads as the durable task graph so the work story survives those breaks.

The graph is not just a todo list. It holds the recovery facts a future agent needs: what was requested, what was changed, what evidence was collected, what was rejected, what still blocks the work, and how the result was validated.

  1. The user request defines the scope and intent.
  2. Beads records tasks, dependencies, comments, and evidence.
  3. A closure-memory comment captures what a future agent needs.
  4. A later agent can resume from the durable record.

This is the main reason CWO scales beyond a single prompt. The chat can be compacted or lost, but the project still has a work graph with the accepted story.

Cold-Start Example

Imagine a docs refactor that took three sessions. The original transcript is gone, but the Beads record says the homepage was changed for novice readers, validators were updated, Pages passed, and a follow-up remains for deep-dive documentation. A new agent can start from that record instead of asking the operator to reconstruct the entire story.

Without durable memory The agent sees a vague summary and must rediscover scope, decisions, and validation.
With Beads memory The agent reads the task, dependencies, evidence, closure-memory comment, residual risk, and next action.

Closure Memory

The close reason should stay short. The useful memory belongs in the final comment before closing meaningful work. That comment should answer who was involved, what changed, why the bead is closing, how it was validated, when it closed, where it ran, what decisions were made, what evidence matters, what risk remains, and what should happen next.

Practical effect: spawned agents with no transcript, or compacted sessions after context compaction, can read the Beads brief and recover the important story without replaying the whole conversation.

Context Depth

CWO does not make every agent read everything. The prompt coach sizes Beads context depth for the work:

  • none: no Beads lookup.
  • summary: assigned-bead fields without comments.
  • focused: assigned-bead comments as internal evidence.
  • heavy: broader related history for prior-work or synthesis-heavy tasks.
  • audit: incident, quarantine, sabotage, credential, or forensic review.

Comment-bearing depths are for internal Codex or subagent briefing: outside reviewers receive packets that have been boundary-checked, not the internal work graph.

Local And Shared

A Beads graph is useful even when it is local-only. In that mode, it preserves the story on this machine but does not imply that another workstation can see it. If the repository has a shared Dolt-backed Beads remote and the operator syncs it, the same graph can become a handoff surface for other collaborators.

The key rule is simple: record what actually happened. If the graph was local-only, say so. If it was synced, record the proof. The durable memory is valuable because future agents can trust its boundaries.
