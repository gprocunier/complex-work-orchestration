Create a separate disposable project

From the source checkout, ~/cwo-source, copy the starter into a new folder. The copy command refuses an existing destination.

Long commands keep their original lines. If a line continues beyond the edge, scroll inside its code block; select the text to copy it.

Terminal

cd "$HOME/cwo-source"
python3 scripts/create_first_project.py "$HOME/cwo-first-project"
cd "$HOME/cwo-first-project"
git init
python3 -m unittest -v

Expected: the tests fail. This is deliberate: the starter accepts invalid ports and does not reject non-object input correctly. If tests cannot import checker, check that pwd names cwo-first-project, not the source checkout.

Save a disposable baseline before the agent edits anything:

Terminal

git add checker.py test_checker.py service.json invalid.json README.md .gitignore
git -c user.name="Tutorial" -c user.email="tutorial@example.invalid" commit -m "Save disposable starter"
git tag cwo-tutorial-start
bd init --prefix cwo-demo

Expected: Git records the starter, the local tag names that restore point, and Beads initializes local task storage. Beads may create project-local agent instructions and ignore entries; inspect those generated setup files rather than mistaking them for the checker repair. If Beads requests a database service or backend setup, follow its version-specific instructions; do not proceed until bd ready --json works in this project. No task may be ready yet; an empty list is fine. Do not configure a remote just for the tutorial.

Start the project agent in the right folder

Terminal

cd "$HOME/cwo-first-project"
cwo-codex -C "$HOME/cwo-first-project"

Expected: a new Codex session in the disposable project. If cwo-codex is not on your PATH, use this alternative instead:

Terminal

codex --profile cwo-sol-operator-e -C "$HOME/cwo-first-project"

Use a fresh session to load the named profile. If startup rejects the configured model, follow startup recovery before proceeding.

Ask for the repair and saved decision

Before starting: use only the generated synthetic files. Prompts and selected project context go to your configured provider and consume its applicable quota. The checker must not contact the configured host.

Prompt inside Codex

Use $complex-work-orchestration in this disposable project. I authorize in-thread maintenance of checker.py.

Read README.md and the tests. Create a validator task and a CLI task blocked by it; record both IDs. Fix only errors(config), preserving its list-of-messages interface. Reject boolean ports. Leave the CLI unimplemented and its task open.

Run the tests without weakening them, inspect the diff, and accept the validator task only after its checks pass. Write HANDOFF.md with accepted behavior, evidence, task IDs, and the next step.

Use only the existing local Beads backend. No delegation, service-host contact, tool-initiated external network requests, commits, pushes, publication, or global configuration changes. Stop after this phase.

What you should see: a changed checker.py, passing validator tests, two task IDs and HANDOFF.md. You decide whether the behavior meets your need; CWO keeps the decision with its checks and dependent work.

Open a second terminal in the practice directory to inspect the result. With one terminal, let the agent finish and exit the client first.

Terminal

cd "$HOME/cwo-first-project"
python3 -m unittest -v
git status --short
git diff cwo-tutorial-start -- checker.py test_checker.py
cat HANDOFF.md
bd list --all

Continue when: tests pass without weakened assertions, the validator is accepted, and the CLI task is still open with the validator as its prerequisite. The handoff must explain why boolean ports are invalid. If something is missing, ask the agent to correct it before leaving.
