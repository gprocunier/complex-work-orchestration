Practice example: fix a small Python program

This is a simple, optional practice exercise using supplied sample files—not work on your own project. You will practise asking for a small fix, inspecting the changes and tests, and saving a handoff.

The supplied checker.py is a deliberately broken Python program that checks a service configuration: a server name and port number. First, ask CWO to fix its validation and save the results. On the next page, a fresh agent session will use that record to add a command-line interface (CLI)—a command you can run from your terminal.

Already installed CWO and ready for your own task? Use CWO on your own project instead.

Create a separate disposable project

A configuration such as {"host": "localhost", "port": 8080} should pass. An empty server name or an invalid port should produce useful errors. The program only checks the file; it must never connect to the server. Copy the starter from ~/cwo-source into a new, disposable project below. The copy command refuses an existing destination.

Terminal

cd "$HOME/cwo-source"
python3 scripts/create_first_project.py "$HOME/cwo-first-project"
cd "$HOME/cwo-first-project"
git init
python3 -m unittest -v

Expected: the tests fail. The starter deliberately accepts invalid values, such as true as a port number, and mishandles input that is not a JSON object. The tests describe the required behavior; do not change them to make the failure disappear. If tests cannot import checker, check that pwd names cwo-first-project, not the source checkout.

Save the untouched starter in Git before the agent edits anything. The tag marks this version so you can compare changes or restore the practice files later:

Terminal

git add checker.py test_checker.py service.json invalid.json README.md .gitignore
git -c user.name="Tutorial" -c user.email="tutorial@example.invalid" commit -m "Save disposable starter"
git tag cwo-tutorial-start
bd init --prefix cwo-demo

Expected: Git records the starter files and a local restore tag; Beads creates task storage for this project. Inspect any agent instructions or ignore entries Beads creates—they are setup files, not the checker repair. Follow your Beads version’s database instructions if needed. Continue only when bd ready --json works here; an empty task list is fine. No remote is needed for this tutorial.

Start the project agent in the right folder

Terminal

cd "$HOME/cwo-first-project"
cwo-codex -C "$HOME/cwo-first-project"

Expected: a new Codex session in the disposable project. If cwo-codex is not on your PATH, use this alternative instead:

Terminal

codex --profile cwo-sol-operator-e -C "$HOME/cwo-first-project"

Use a fresh session to load the named profile. If startup rejects the configured model, follow startup recovery before proceeding.

Fix validation and record the verified result

Before starting: use only the generated synthetic files. Prompts and selected project context go to your configured provider and consume its applicable quota. The checker must not contact the configured host.

What you will accomplish

Fix errors(config), the function that returns validation messages. Valid input must be a JSON object with a nonempty server name and an integer port from 1 to 65,535: a whole number, not text or a decimal value. Boolean values (true and false) mean yes or no; they are not port numbers. Keep the existing list-of-messages interface. Leave the command-line interface for the next session.

Stop after fixing validation. Save which requirements were checked, which tests passed and what remains in Beads and HANDOFF.md, a short project handoff file. The next session must recover that information from the saved records, not the earlier conversation.

Prompt inside Codex — copy the complete block

Use $complex-work-orchestration in this disposable project. I authorize in-thread maintenance of checker.py.

Read README.md and the tests. Create a validator task and a CLI task blocked by it; record both IDs. Fix only errors(config), preserving its list-of-messages interface. Reject boolean ports. Leave the CLI unimplemented and its task open.

Run the tests without weakening them, inspect the diff, and accept the validator task only after its checks pass. Write HANDOFF.md with accepted behavior, evidence, task IDs, and the next step.

Use only the existing local Beads backend. No delegation, service-host contact, tool-initiated external network requests, commits, pushes, publication, or global configuration changes. Stop after this phase.

Look for a changed checker.py, passing validator tests, two task IDs and HANDOFF.md. One task covers the validation fix; the other covers adding the terminal command and must wait for the fix to pass its checks. Check that boolean ports are rejected and that the second task has not started. You decide whether the result meets the requirements.

Open a second terminal in the practice directory to inspect the result. With one terminal, let the agent finish and exit the client first.

Terminal

cd "$HOME/cwo-first-project"
python3 -m unittest -v
git status --short
git diff cwo-tutorial-start -- checker.py test_checker.py
cat HANDOFF.md
bd list --all
bd show VALIDATOR_TASK_ID --json
bd show CLI_TASK_ID --json

Replace VALIDATOR_TASK_ID and CLI_TASK_ID with the actual IDs in HANDOFF.md. Inspect both records: the validator is accepted and the still-open CLI depends on it.

Continue when: tests pass without weakened assertions, the validator task is accepted, and the command-line task is still open with the validator as its prerequisite. The handoff must record the validation requirements, the checks that passed and the next task. If something is missing, ask the agent to correct it before leaving.
