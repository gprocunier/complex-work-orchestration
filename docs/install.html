Install and verify CWO

Install the CWO skill and a named Codex profile: a set of CWO-specific settings selected when you start a session. Verify both before starting the optional practice example.

If you want your agent to install this skill, give it this

Copy this prompt into an ordinary Codex CLI session. It does not require CWO to be installed. Your agent checks the machine, sets up missing prerequisites within your permissions, installs CWO and verifies the result.

Show the installation prompt 
Install Complex Work Orchestration (CWO) for my local Codex CLI setup.
CWO is not installed yet: use ordinary tools and a short setup checklist,
not CWO commands or a CWO work graph, to get started.

Repository: https://github.com/gprocunier/complex-work-orchestration
CWO setup: https://gprocunier.github.io/complex-work-orchestration/install.html
Codex setup: https://learn.chatgpt.com/docs/cli
Beads setup: https://beads.gascity.com/getting-started/installation

1. Check this machine first.
Identify the OS, shell, starting directory and intended Codex home. Check
Bash, Git, Python 3, Codex CLI and Beads (bd), including their versions.
Inspect CODEX_HOME and CODEX_SKILLS_DIR without displaying credentials.
Confirm Codex account access using its documented checks; a version string
alone is not proof of authentication. Let me complete any sign-in myself.

2. Set up missing prerequisites.
Use the current official OS/vendor instructions for this platform. Install
only what is missing, within my existing permissions. Explain the exact
change and request approval when elevated privileges, a new package source
or an otherwise unpermitted change is needed. Do not bypass the sandbox,
weaken security settings, collect credentials or overwrite my configuration.
The CWO walkthrough has been checked on Linux; do not assume it proves
support on another platform. Report an unsupported step rather than improvise.

3. Verify Beads task storage, not just the bd executable.
Follow the instructions for the installed Beads version and build. Set up a
local backend such as Dolt only if that version needs it; do not replace or
migrate an existing working backend. In a new disposable scratch project,
use that version's documented initialization and run bd ready --json.
Isolate its database and any service from my existing projects and task data.
An empty ready list is valid; a connection error is not. Record the test's
location and stop only temporary services you started. Do not configure a
remote, publish task records or initialize Beads in my real project yet.
If storage cannot be verified, report that gap rather than claim full setup.

4. Get and inspect CWO's source.
Use a separate source folder, outside the installed skill and my project.
For example, use ~/cwo-source only if that folder does not already exist.
Clone the repository above and record its origin and commit. Never delete,
reset or overwrite an existing checkout; inspect it and use the update guide
or a new folder instead. Read its repository instructions, README.md,
docs/install.html, scripts/install.sh and scripts/manage_instruction_profile.py
before running the installer. Do not require an installed CWO to do this.

5. Install the skill and its named settings profile.
From the source checkout, inspect the installer's dry-run destination first.
The following commands use the default paths. If I use CODEX_HOME or
CODEX_SKILLS_DIR, use each helper's --help to align installation, checking,
profile and launcher with that same intended setup; do not unset overrides
or install into a second home by accident.

./scripts/install.sh --yes --dry-run
./scripts/install.sh --yes
python3 scripts/check_installed_skill.py --check
python3 scripts/manage_instruction_profile.py install --profile operator-e
python3 scripts/manage_instruction_profile.py verify --profile operator-e

Inspect any existing installation and preserve its local changes and backup.
Do not use --force to overwrite a modified profile or launcher without asking
which version to keep. Leave my default Codex settings unchanged. A dry run
has not installed anything; a missing-bd warning is not verified task storage.

6. Verify and hand back a usable starting point.
Require the skill check to report current and profile verification to report
"ok": true. Report failures separately; do not label a partial install ready.
Check that the launcher can be found, or give its full path. If the profile's
model is unavailable, report it and propose a supported per-session override
that retains the named profile; do not silently rewrite defaults.

Summarize the source commit, installed paths, prerequisite/backend checks,
backups, actual verification results and any remaining blocker. Give me the
command to start a fresh CWO session, explaining how to supply my project
directory. Do not start project work or launch additional models. Explain
that this existing conversation has not acquired the new instruction profile.

You handle account sign-in and any required approvals. The prompt does not authorize project work, extra model calls or changes to your default Codex settings. Prefer to install by hand? Follow the commands below.

Keep source, installed files and project separate

Use three separate folders: the source checkout contains the installer; the installed skill normally lives at ~/.codex/skills/complex-work-orchestration; your target project contains the work Codex will change.

The following primary path assumes ~/cwo-source does not already exist. If it does, choose a new source folder or follow the update guide; do not delete an existing checkout.

Terminal

git clone https://github.com/gprocunier/complex-work-orchestration.git "$HOME/cwo-source"
cd "$HOME/cwo-source"
./scripts/install.sh --yes
python3 scripts/check_installed_skill.py --check
python3 scripts/manage_instruction_profile.py install --profile operator-e
python3 scripts/manage_instruction_profile.py verify --profile operator-e

Expected: the installer reports its destination, the skill check reports current, and profile verification reports "ok": true. The named profile adds CWO instructions and a launcher without changing your default profile settings. The installed skill remains discoverable in ordinary sessions until disabled or removed. If a managed file has local changes, inspect the reported path before deciding what to keep; do not add --force blindly. Resolve a missing bd warning before continuing.

These commands use the default Codex home. If you deliberately use CODEX_HOME or CODEX_SKILLS_DIR, align the installer, check, profile, and launcher with that same home. The installation reference covers explicit destinations.
