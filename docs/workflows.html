Workflows

Use the skill from inside Codex first. Codex runs the coach, turns answers into a Beads-backed plan, and only then opens contractor or local-worker lanes when the policy says they fit.

Invoke From Codex

The normal interface is a Codex request, not a manual tour of helper scripts. Ask for the skill and prompt coach in /plan; Codex can run the local tools, summarize the route, and ask only the choices that change execution.

Coach And Decide

The coach decides whether the work should stay in-thread, use a lightweight Beads task, scaffold a full harness, or add publish gates. If the route involves outside sharing or local inference, Codex asks for that explicit boundary before any packet exists.

What Codex may run behind the scenes: 

python3 scripts/coach_prompt.py --json \
  "Create a publish-ready documentation pass for the project."

python3 scripts/route_work.py \
  "Create a publish-ready documentation pass for the project."

Contractor deep dive: share boundaries, job labels, packet gates, and returns. Local worker deep dive: OpenShift AI profiles, OpenAI-compatible endpoints, and guardrails.

Local-worker lane from inside Codex: 

/plan Use $complex-work-orchestration prompt coach to size this work:
Use a local OpenShift AI vLLM worker to review a bounded README command example.
python3 scripts/coach_prompt.py \
  --local-ok \
  --prefer-local \
  --local-profile openshift-ai-vllm \
  --requested-role documentation \
  "Use an OpenShift AI vLLM local worker to review a bounded README command example."

python3 scripts/dispatch_work.py \
  --local-ok \
  --prefer-local \
  --local-profile openshift-ai-vllm \
  --dispatch-id dispatch-example \
  --bead example \
  --json \
  "Summarize docs-review risks."
Local rule: --local-ok is explicit opt-in. Use --prefer-local only when local routing is intended, and --execute-local only when the operator approves a real endpoint call. 
python3 scripts/build_contractor_packet.py \
  --bead "$BEAD_ID" \
  --executor claude_code_manual \
  --share-boundary redacted-packet \
  --external-ok \
  --epic "$EPIC_ID" \
  --format json \
  --output contractor-packet.json

python3 scripts/dispatch_work.py \
  --packet contractor-packet.json \
  --mode manual \
  > contractor-dispatch-prompt.md
# Operator-executed external calls:
claude -p "$(cat contractor-dispatch-prompt.md)" \
  > contractor-return.md

agy -p "$(cat contractor-dispatch-prompt.md)" \
  > contractor-return.md
Boundary rule: Use --external-ok only after the user approves third-party sharing. Use --allow-disclosure-escalation for repo-readonly or patch-branch packets.

Validate And Handoff

Validation is the final gate, not a cleanup step. Record commands, evidence, screenshots, return evaluation, and residual risk in Beads before the architect accepts the work. 

python3 scripts/normalize_contractor_return.py \
  --bead "$BEAD_ID" \
  --dispatch-id "$DISPATCH_ID" \
  --packet-sha256 "$PACKET_SHA256" \
  --file contractor-return.md \
  --output contractor-return-bundle.json

python3 scripts/evaluate_return.py \
  --bead "$BEAD_ID" \
  --file contractor-return.md

For ordinary docs or release work, validation also includes repository checks, site checks, tests, install smoke, visual render checks, and publish sanitization before any upstream push.
