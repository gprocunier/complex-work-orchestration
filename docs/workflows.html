Workflows

Run the helper scripts from inside Codex, let the main thread act as project manager, and hand a bounded contractor prompt to Claude or agy only after the packet gate passes.

Inside Codex

The helper scripts are normal repository tools. When a user asks Codex to use the prompt coach or orchestration harness, the main Codex thread can run those scripts in the workspace and turn the result into a plan, Beads graph, or contractor packet. The user does not need to leave Codex unless they want automation or a separate operator shell.

Contractor Dispatch

Contractor dispatch has two stages. The main thread prepares and audits the packet; the operator chooses whether to hand the final prompt to an external CLI. The helpers do not secretly call Claude, agy, or any other outside model.

python3 scripts/build_contractor_packet.py \
  --bead "$BEAD_ID" \
  --executor claude_code_manual \
  --share-boundary redacted-packet \
  --external-ok \
  --epic "$EPIC_ID" \
  --format json \
  --output contractor-packet.json

python3 scripts/dispatch_work.py \
  --packet contractor-packet.json \
  --mode manual \
  > contractor-dispatch-prompt.md
# Operator-executed external calls:
claude -p "$(cat contractor-dispatch-prompt.md)" \
  > contractor-return.md

agy -p "$(cat contractor-dispatch-prompt.md)" \
  > contractor-return.md
Boundary rule: Use --external-ok only after the user approves third-party sharing. Use --allow-disclosure-escalation for repo-readonly or patch-branch packets.

Returns

Contractor output is evidence, not implementation authority. Normalize it, evaluate it, and let the architect decide whether any finding becomes normal Codex-executable work. 

python3 scripts/normalize_contractor_return.py \
  --bead "$BEAD_ID" \
  --dispatch-id "$DISPATCH_ID" \
  --packet-sha256 "$PACKET_SHA256" \
  --file contractor-return.md \
  --output contractor-return-bundle.json

python3 scripts/evaluate_return.py \
  --bead "$BEAD_ID" \
  --file contractor-return.md

Quarantine, malpractice, provider-conflict, and peer-review signals block implementation dependencies until architect adjudication is complete.
