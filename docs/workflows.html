One change, several acceptance conditions

The task was to add machine-readable reporting to the existing documentation-audit CLI. Human output, the list-of-errors API and exit statuses had to stay compatible. The goal was local release readiness, not deployment.

A review finding changed the implementation

The first candidate passed eight tests. Independent review noticed that a missing café.md link would crash JSON output when stdout used ASCII. The lead reproduced that failure, changed JSON escaping, and added an actual subprocess regression. The resulting strings stay intact when a consumer decodes the report.

Observed finding: the Unicode test used an in-memory string stream, so it could not expose the encoding failure of a real process.

Eleven focused tests passed, including forced-ASCII JSON output, exact Boolean types, human subprocess compatibility and usage errors. Inspect the work record and reproduction commands.

Execution scope: observed local CLI maintenance with independent internal specialist review. It does not demonstrate supervised native-worker execution or native concurrency. The saved handoff is prepared; fresh-agent continuation of this case has not yet been observed.

Keep prerequisites with the work

A durable work graph is a set of saved tasks and their dependencies. In this case, the accepted contract constrained implementation; the reviewed implementation and corrected checks constrained integration. An initial isolated prototype preceded the finer subtask records. Those records gate accepted integration, not a backdated plan.

Start larger work with the result you need

Prompt inside Codex

Use $complex-work-orchestration to prepare this CLI change for local release readiness. Preserve human output and exit statuses while adding a versioned JSON report. Identify acceptance checks, dependencies and writable paths before integration. Use an independent specialist review through an available authorized route. Record actual findings, decisions, checks and the next step. Do not publish, deploy, install into a live environment or share with additional outside parties.

You supply the goal, constraints and permission. The lead organizes the task records, bounds assignments, checks the returned evidence and resolves findings. Native subagents provide delegation; Beads handles task state; an instruction file alone cannot supply every execution control.

Choose a specialist route

Start with the question and available execution capability, then choose the permitted route. Advice is evaluated before it changes implementation.

  • Native implementation or checking: verify exact worker and host admission. Qualification, scope and fixed-cohort controls apply.
  • Internal review: use the authorized read-only reviewer route for a bounded question. It does not qualify a productive worker.
  • Outside review: agree the sharing boundary, then build and validate the minimized packet. Outside sharing needs explicit opt-in.
  • Local inference: check the configured local-model path and its explicit opt-in.

What it costs

Records, repeated checks and specialist calls take time and model quota. A short disposable task may need only one thread. Use the extra structure when dependencies, reviewers or a later session need the same accepted decisions. Native concurrency remains a host-qualified preview; released capacity is not proof that your session can use it.

Do not substitute a delegated worker model when admission fails. Check the execution requirements and continue only independently permitted work.

When a task cannot continue

Preserve its evidence and identify what stopped. Reviewer disagreement needs a decisive check and an owner decision; a failed worker needs containment and owned-state verification. A spent attempt requires a fresh allowance, not a silent retry. Independently ready work may continue only when its own gates pass.

The authored retry exercise is a separate teaching aid for reasoning about contradictory proposals.

What survives a session

Project files, saved task decisions and validation artifacts can be read again. An unrecorded conversation cannot be assumed to survive. See how a new session uses the durable record.

Check the sharing boundary

No-outside-sharing is the default for additional contractors. Your configured model provider still processes selected agent context. Review permissions before adding sensitive files; use the reference for exact boundaries.
