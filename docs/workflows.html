How-to

Workflows

Use the skill from inside Codex first. Codex runs the coach, turns answers into a Beads-backed plan, and only then opens contractor, local-worker, or review-worker workstreams when the policy says they fit.

The normal interface is a Codex request, not a manual tour of helper scripts. Ask for the skill and prompt coach in /plan; Codex can run the local tools, summarize the route, and ask only the choices that change execution.

Coach And Decide

The coach decides whether the work should stay in-thread, use a lightweight Beads task, scaffold a full harness, or add publish gates. If the route involves outside sharing or local inference, Codex asks for that explicit boundary before any contractor handoff packet exists. A packet is a policy-checked bundle of share boundary, job labels, task context, and approved snippets prepared for outside or local review.

What Codex may run behind the scenes, or what an operator may run directly for advanced automation and troubleshooting: 

python3 scripts/coach_prompt.py --json \
  "Publish-ready documentation pass."

python3 scripts/route_work.py \
  "Publish-ready documentation pass."

python3 scripts/cleanup_stale_agents.py --json

Stale-agent cleanup runs before launch. It cleans harness-owned stale sessions while protecting the current Codex process tree. Run it from the target workspace, or pass --workspace-root when Codex was launched from a broader parent directory. Use --terminate-unowned-codex only for an explicit operator cleanup of stale unowned Codex, Claude, or Agy processes.

Beads Task Graph

Beads is mandatory durable memory. A Beads task graph is the work ledger of tasks, dependencies, evidence, and handoff state. For narrow work, use one task. For broader work, Codex creates an epic with workstreams for architect framing, implementation, review, validation, handoff, and publish-sanitization. Public docs and GitHub Pages work adds a publication review so documentation, web design, and final editorial review converge before validation is accepted.

Optional Workstreams

Contractors and local workers are specialized workstreams selected by the coach and route, not separate starting points. Use them only after the user approves the relevant sharing or local-inference boundary.

A packet validation checkpoint verifies the share boundary, opt-in basis, disclosure level, artifact whitelist, expert profile, and packet integrity before a manual dispatch prompt is rendered.

Local-worker workstream from inside Codex: 

/plan Use $complex-work-orchestration prompt coach:
OpenShift AI vLLM local review of README command examples.

After explicit opt-in, Codex may run helper equivalents behind the scenes. Use direct execution only for advanced automation or troubleshooting: 

python3 scripts/coach_prompt.py \
  --local-ok \
  --prefer-local \
  --local-profile openshift-ai-vllm \
  --requested-role documentation \
  "OpenShift AI vLLM local review of README command examples."

python3 scripts/dispatch_work.py \
  --local-ok \
  --prefer-local \
  --local-profile openshift-ai-vllm \
  --dispatch-id dispatch-example \
  --bead example \
  --json \
  "Summarize docs-review risks."
Local rule: --local-ok is explicit opt-in. Use --prefer-local only when local routing is intended, and --execute-local only when the operator approves a real endpoint call.

Outside-contractor workstream after explicit sharing approval: 

python3 scripts/build_contractor_packet.py \
  --bead "$BEAD_ID" \
  --executor claude_code_manual \
  --share-boundary redacted-packet \
  --external-ok \
  --epic "$EPIC_ID" \
  --format json \
  --output contractor-packet.json

python3 scripts/dispatch_work.py \
  --packet contractor-packet.json \
  --mode manual \
  > contractor-dispatch-prompt.md
# Operator-executed external calls:
claude -p "$(cat contractor-dispatch-prompt.md)" \
  > contractor-return.md

agy -p "$(cat contractor-dispatch-prompt.md)" \
  > contractor-return.md
Boundary rule: Use --external-ok only after the user approves third-party sharing. Use --allow-disclosure-escalation for repo-readonly or patch-branch handoff packets.

Contractor Demo

The public hello-world contractor demo shows this flow end to end. Codex created a small static project, opened a Beads graph, assigned one Antigravity docs branch through agy -p, assigned one Claude Code Pages branch through claude -p, evaluated the returns, repaired public-doc issues, integrated accepted work, and verified GitHub Pages.

The lesson for normal use is that outside CLIs are dispatch targets, not project owners. Use the case study for the concrete branch, artifact, return-review, and publish-gate details.

Validate And Handoff

Validation is the final gate, not a cleanup step. Record commands, evidence, screenshots, return evaluation, and residual risk in Beads before the architect accepts the work. 

python3 scripts/normalize_contractor_return.py \
  --bead "$BEAD_ID" \
  --dispatch-id "$DISPATCH_ID" \
  --packet-sha256 "$PACKET_SHA256" \
  --file contractor-return.md \
  --output contractor-return-bundle.json

python3 scripts/evaluate_return.py \
  --bead "$BEAD_ID" \
  --file contractor-return.md

For ordinary docs or release work, validation also includes repository checks, site checks, tests, install smoke, visual render checks, editor-gate evidence when public docs/pages are in scope, and publish sanitization before any upstream push.
