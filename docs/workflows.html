Start with the task you need to finish

For your own project, start with Prompt Coach to define the result, size planning through validation and decide whether second opinions would help. Follow the multi-model planning example to see how separate findings change a draft plan before any implementation begins.

Use these procedures when a project needs more than a single edit: comparing approaches, resolving reviews, continuing from a handoff or recovering after a worker stops. The lead is the coordinating agent. It checks requirements and evidence and can act only within the permissions you gave it.

  • Compare approaches without changing the requirements — use the project prompt, then adapt the configuration-migration example.
  • Resolve a design disagreement — choose a specialist route and a check that can settle the disagreement. The retry example shows the question to resolve.
  • Continue from accepted work — inspect the handoff and prerequisite checks before taking the next task.
  • Recover after a worker stops — verify that it has stopped, inspect its files and allowance, and identify independent work that may still proceed.

Start larger work with the result you need

Prompt inside Codex

Use $complex-work-orchestration for this project. Establish the requested result and compatibility requirements from the project files before editing. Identify acceptance checks, dependencies and writable paths before integration. Use an independent specialist review through an available authorized route. Record actual findings, decisions, checks and the next step. Do not publish, deploy, install into a live environment or share with additional outside parties.

For evaluation work: record the fixed case set, compatibility requirements, scoring and selection rule. Ask the lead to bind and invoke the frozen-protocol check before candidate work, and record its result. A blocked check stops candidate work under that evaluation. Changed criteria require a new evaluation. Describe the evaluation as gated only when that check was actually invoked.

You supply the goal, requirements and permission. The lead records the tasks, limits each assignment, checks the results and resolves review findings. Codex supplies the agent tools; Beads stores the task state. CWO’s instructions and helpers connect that work.

Choose how to get specialist help

Choose the question first, then check which permitted tools and reviewers are available. Review advice before using it to change the project.

  • Delegate implementation or checks inside Codex: verify the exact worker, tools, host and assignment before launch. See native delegation requirements.
  • Request an internal review: use an authorized read-only reviewer for a specific question. A successful review does not qualify that reviewer to edit files.
  • Use an outside model: first agree what may be shared and with whom, then build and validate a brief containing only that material. Outside review requires explicit opt-in.
  • Use a local model: explicitly opt in and check the configured endpoint. See local-model setup.

Keep prerequisites with the work

A work graph is a saved list of tasks and their dependencies. Before starting a task, inspect the accepted result it depends on. In the documentation-checking example, the new JSON report had to preserve existing behavior. A review finding delayed acceptance until an encoding failure was fixed.

Inspect a handoff before continuing

  1. Confirm the project directory and current source changes.
  2. Read the accepted behavior, actual checks and unresolved work in HANDOFF.md.
  3. Inspect the named task IDs and prerequisite states.
  4. Rerun the relevant checks before starting dependent work.

When a worker stops or a review remains unresolved

First identify the problem. For conflicting advice, record the disagreement and find a check that can resolve it. For a failed worker, verify that it has stopped, inspect what it changed and account for the allowance already used. An attempt that has ended needs a separately permitted new allowance, not a silent retry. Continue unrelated work only when its own requirements, permissions and safety checks pass.

The retry exercise shows how a concrete test can resolve conflicting advice.

See the task graph for an ended attempt, a waiting dependency and independent work.

What it costs

Records, repeated checks and specialist calls take time and model quota. A short disposable task may need only one thread, but it still needs access limits and evidence checks. Add saved dependencies, specialist reviews and handoffs when they help the task. Using fewer coordination steps is not a reason to trust the model implicitly. Running multiple Codex workers at once remains a preview. The host must pass the required checks; a published worker limit does not prove that your session can use it.

Do not substitute a delegated worker model when admission fails. Check the execution requirements and continue only independently permitted work.

What survives a session

Project files, saved task decisions and validation artifacts can be read again. An unrecorded conversation cannot be assumed to survive. See how a new session uses the durable record.

Check the sharing boundary

Additional outside review is off by default. Your normal model provider still receives selected agent context. Check permissions before adding sensitive files; the reference links the exact sharing rules.
