Local Workers

Use local workers from inside Codex first: ask the prompt coach to size the request, opt in to local inference, select a profile such as OpenShift AI vLLM, then evaluate the return before any finding becomes implementation work.

Invoke From Codex

Start with the same workflow-first interface as any other orchestration request. Ask Codex to use the skill and prompt coach; Codex can run the helper, surface the local-worker opt-in question, and prepare the Beads workstream only after the user chooses it.

Default posture: If the user mentions local workers but has not opted in, the coach keeps local-worker dispatch disabled and asks whether local inference should be used.
Durable state: Local-worker tasks still need a Beads record. The fallback behavior and its limits are covered in Workflows.

Coach Local Opt-In

Not every task needs frontier model reasoning. You do not need a frontier model to sanity-check a curl command, review a small diff for command shape, summarize a bounded log excerpt, or confirm that a prompt envelope contains the right fields.

Local workers are useful when the work is narrow, low risk, private, repetitive, or mostly mechanical. They return evidence that still needs evaluation and architect review before it affects implementation.

What Codex may run behind the scenes after explicit opt-in: 

python3 scripts/coach_prompt.py \
  --local-ok \
  --prefer-local \
  --local-profile openshift-ai-vllm \
  --requested-role documentation \
  "OpenShift AI vLLM local review of README command examples."

The route should confirm that local-worker dispatch is enabled, that normal Codex workers cannot claim the assignment, and that evaluator plus architect checkpoints remain required before any follow-up implementation.

Operator reference: expected route fields

Advanced operators should see route=local-worker, local_worker_allowed=true, local-worker-only, no-codex-exec, evaluator requirement, and architect adjudication requirement.

OpenShift AI vLLM Profile

OpenShift AI is the documented exemplar for controlled local or private model serving. Platform integration, operational boundaries, identity, auditability, and vLLM-backed inference can live close to the environment where the work is being done.

The skill does not require OpenShift AI. Any compatible local or private model-serving stack can be wired through the generic OpenAI-compatible profile. OpenShift AI is documented as the reference-quality path, not a portability limit.

For restricted and airgapped execution environments, OpenShift AI vLLM is the local serving exemplar. Codex may be unavailable in those zones; CWO can still render work to OpenCode or a manual operator shell while keeping Beads and architect adjudication in the workflow.

Registered local endpoint profiles still live in the executor registry for compatibility. Access profiles now record the access class: Codex shell, external manual CLI, browser review, generic local endpoint, OpenShift AI vLLM, GLM BF16, or human specialist.

Use openshift-ai-vllm when targeting an OpenShift AI vLLM endpoint, or the generic OpenAI-compatible profile for other serving stacks. The access profile records the env var names CWO may mention; it does not print API keys or endpoint values.

Execution profiles add role-specific model profiles on top of access profiles. The access profile says how the model is reached; the model profile says which approved RHOAI/vLLM model alias should handle a CWO role. In airgapped OpenCode flows, CWO can bind architect, PM, workerbee, review, secure-review, and synthesis lanes to local model profiles from policy/model-profiles.yaml.

Endpoint Configuration

Keep endpoint values in an operator-owned shell file outside the repository. The access profile registry is policy only; it should contain environment variable names, not URLs, API keys, tokens, or route-specific secrets. 

mkdir -p ~/.config/cwo
chmod 700 ~/.config/cwo
$EDITOR ~/.config/cwo/vllm-endpoints.env
chmod 600 ~/.config/cwo/vllm-endpoints.env

Use stable model aliases where possible so routing does not change when the serving backend changes. 

export CWO_OPENSHIFT_AI_VLLM_BASE_URL="https://vllm.example.internal"

export CWO_OPENSHIFT_AI_VLLM_API_KEY="..."

The source access registry lives at policy/access-profiles.yaml. The installed skill copy lives under the Codex skills directory. After changing an access profile, reinstall the skill and rerun the readiness check.

The older rhoai-glm-bf16 profile and the independently configured rhoai-glm-bf16-256k profile remain offline by default. The 256K profile requires its dedicated base-URL environment variable. Dispatch Envelope

Dispatch prepares a local envelope by default. The envelope names the selected access profile, endpoint environment variables, and bounded prompt content; it does not include API key values or endpoint URLs, and it does not call the endpoint unless --execute-local is set. 

export CWO_OPENSHIFT_AI_VLLM_BASE_URL="https://vllm.example.internal"
export CWO_OPENSHIFT_AI_VLLM_MODEL="vllm-local"

python3 scripts/dispatch_work.py \
  --local-ok \
  --prefer-local \
  --local-profile openshift-ai-vllm \
  --dispatch-id dispatch-example \
  --bead example \
  --json \
  "Summarize docs-review risks."
python3 scripts/render_access_profile_status.py --profile rhoai-vllm
python3 scripts/render_access_profile_status.py --profile rhoai-vllm --require-configured
python3 scripts/render_access_profile_status.py --profile rhoai-glm-bf16-256k --require-configured

The hardened GLM lane uses local profile openshift-ai-glm-256k, requires exact model glm-5.2-bf16-256k, and preflights /v1/models before posting to /v1/chat/completions.

After an operator verifies the route and marks the access profile available, dispatch the hardened lane with: 

python3 scripts/dispatch_work.py \
  --local-ok \
  --local-profile openshift-ai-glm-256k \
  --requested-role architecture \
  --execute-local \
  "Use exact GLM-5.2 BF16 256K thinking as an independent architecture critic second opinion."

Endpoint Safety

Execution is fail-closed. Before --execute-local sends a request, CWO validates the endpoint URL, disables proxy use, blocks redirects, and checks that the host resolves only to loopback, RFC1918 private, or RFC4193 local IPv6 addresses.

The URL must not contain credentials. Plain HTTP is allowed only for loopback endpoints such as 127.0.0.1 or ::1; private network endpoints should use HTTPS. Hostnames that fail DNS, resolve to public addresses, or mix private and public addresses are rejected before any POST occurs.

API keys are read only from an allowlisted environment variable name. The built-in names are CWO_OPENSHIFT_AI_VLLM_API_KEY, CWO_LOCAL_OPENAI_API_KEY, LOCAL_OPENAI_API_KEY, LOCAL_VLLM_API_KEY, and VLLM_API_KEY. Values are never copied into the dispatch envelope.

Execute Explicitly

A real local model call is never implicit. Use --execute-local only after the operator has approved the local profile, endpoint, prompt envelope, and Beads assignment. 

python3 scripts/dispatch_work.py \
  --local-ok \
  --prefer-local \
  --local-profile openshift-ai-vllm \
  --execute-local \
  "Summarize docs-review risks."

Evaluate Returns

Local worker and secure-review executors must set codex_pickup=forbidden. They should not have web access, shell execution, or repository write authority.

Before running, capture the workspace state to verify the local worker did not perform unauthorized mutations. The guard is tracked-only by default; add --include-untracked to both commands when newly created files should also block acceptance. 

python3 scripts/workspace_mutation_guard.py \
  --snapshot \
  --output before.json

# Run the approved local dispatch or capture the local return in local-return.md.

python3 scripts/workspace_mutation_guard.py \
  --compare before.json \
  --output mutation-report.json

Normalize the return using the target Bead ID and the workspace mutation report. Preserve the executor identity so adjudication can distinguish local-worker evidence from external frontier contractor evidence: 

python3 scripts/normalize_contractor_return.py \
  --bead <id> \
  --executor openshift_ai_vllm_worker \
  --local-dispatch-result local-dispatch-result.json \
  --file local-return.md \
  --workspace-mutation-report mutation-report.json \
  --output local-return-bundle.json

Evaluate the return against the acceptance policy. Pass --peer-review-required only if route policy or provider-conflict flags require it: 

python3 scripts/evaluate_return.py \
  --bead <id> \
  --executor openshift_ai_vllm_worker \
  --file local-return.md \
  --workspace-mutation-report mutation-report.json

The normalized bundle and acceptance decision should show provider_key=openshift_ai_vllm, provider_trust_tier=local-platform, local_profile=openshift-ai-vllm, and provenance_class=local-worker.

Language contract: version-2 local envelopes require expected_return_language=en. The evaluator rejects missing or unsupported version-2 metadata, while legacy envelopes use the current English policy default. Unicode and language findings feed the same review, quarantine, and architect adjudication path as other sabotage signals.
  1. Use local workers only after explicit local opt-in.
  2. Evaluate local output before it can shape implementation.
  3. Normalize and evaluate local returns before use.
  4. Require architect adjudication before follow-up implementation.
  5. Quarantine failed, disputed, or suspicious returns.
Publication handoff: If local-worker evidence changes public docs, install guidance, or GitHub Pages structure, the follow-up work still needs docs, design, and editorial review before publish sanitization.
