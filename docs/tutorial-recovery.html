Stop or reset the practice project

Stopping the agent, restoring files and removing CWO are different actions. Choose the one you need; none automatically resets the others.

Stop and inspect

Ask the agent to stop and save a handoff. Ending the conversation does not undo edits. This tutorial does not request a delegated worker. If you did launch one separately, verify that it has stopped and released its resources before reusing its workspace. Inspect your files and handoff before starting again.

Restore the practice files

Undo only this example: first confirm the directory and inspect the diff. The restore below discards staged and unstaged tutorial checker/test edits; it is intentionally limited to those files. Keep the handoff and task records if you want the evidence.

Terminal

cd "$HOME/cwo-first-project"
pwd
git status --short
git diff cwo-tutorial-start -- checker.py test_checker.py
git restore --source=cwo-tutorial-start --staged --worktree -- checker.py test_checker.py

Added files may be untracked, staged or committed. Restoring the starter removes the fix, so the earlier completed task and handoff no longer describe the current code. Record that difference before continuing. Inspect git status --short and remove only a specifically identified disposable file if you want to reset it. Do not run a broad clean or delete an arbitrary project folder.

Try the exercise again without erasing its history

Restoring files does not reset task history. Record that the code has returned to the starter version; earlier acceptance still describes the earlier repair. Create new tasks and checks for a new attempt. Do not reopen a stopped worker session or erase its evidence.

Use the complete practice-example instructions for the restored practice files.

Return to ordinary Codex or remove CWO

Return to the default profile: start a fresh ordinary codex -C "$HOME/cwo-first-project" session. That drops the named operator profile, not the installed skill; CWO remains available to skill discovery until disabled or removed. To remove the managed profile and active skill install, run from the source checkout:

Terminal

cd "$HOME/cwo-source"
python3 scripts/manage_instruction_profile.py remove --profile operator-e
./scripts/install.sh --uninstall --yes

Expected: unmodified managed profile/launcher files are removed and the skill is moved out of the active skills directory into a backup. Modified managed files are refused for inspection. This does not delete project files, Beads history, Codex credentials, or all backups. For a custom install, use the same home/destination options you installed with. Troubleshoot a failed step.

If the launcher or model is unavailable

The launcher is not on PATH

Use this command instead of cwo-codex:

Terminal

codex --profile cwo-sol-operator-e -C "$HOME/cwo-first-project"

The profile’s model is rejected

  1. Open an ordinary codex session using the account you checked during preparation. Enter /model to choose a model available to that account, then /status to read the selected model identifier. See the official model-selection instructions. If the ordinary client cannot start or sign in either, resolve that prerequisite first.
  2. Exit the ordinary session. In the next command, replace YOUR_AVAILABLE_MAIN_MODEL with that identifier; it is a placeholder, not a model name.

Terminal — replace the model placeholder before running

codex --profile cwo-sol-operator-e \
  --model YOUR_AVAILABLE_MAIN_MODEL \
  -C "$HOME/cwo-first-project"

Ready when: the fresh session starts in the practice project with the named profile and chosen main-thread model. Record the exact working launch command, selected model and any observed deviation in HANDOFF.md. Reuse that same command for the continuation session rather than falling back to the rejected profile model.

This changes the main thread only. Do not substitute a delegated worker model or disable supervision. Rerun source-checkout profile verification if managed files appear modified.
