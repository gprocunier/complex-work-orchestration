Simple Use Cases

Use the simple path for a focused change that still needs a work record: a small bug fix, a docs cleanup, a validation pass, or a short investigation that another agent may need to resume. 

/plan Use $complex-work-orchestration prompt coach:
Clean up installer docs, tests, and handoff notes.
  1. Codex runs the prompt coach and asks only execution-changing questions.
  2. The work stays in the main thread unless the coach recommends review lanes.
  3. One Beads task captures scope, evidence, validation, and handoff.
  4. The close reason stays short; the final comment preserves the reusable context.

Continue with Get Started for the first run, then use Workflows when the coach recommends a broader graph.

Durable Work Log

Beads is the durable work log. The final closure-memory comment should answer the recovery questions a future agent would ask: who was involved, what changed, why it closed, how it was validated, when it was closed, where it ran, what risk remains, and what follows.

For exact closure helper syntax, use Reference. This page keeps the use-case view focused on why the durable record matters. The Beads Memory deep dive explains the same idea from the perspective of context recovery and agent handoff.

If no Dolt remote is configured, say that the Beads trail is local-only. Do not imply remote sync, shared durability, or completed publication until those checks have actually happened.

Where CWO Fits

CWO is a governance, evidence, and handoff layer for Codex-led work. It does not replace OpenRouter Fusion, LangGraph, AutoGen, CrewAI, Claude Code, Gemini CLI, or Codex CLI. Use those tools for the model call, agent runtime, coding session, or workflow they are built to provide; use CWO to decide when they are appropriate, what boundary they get, how their output is evaluated, and what durable Beads record a future agent can trust.

  • OpenRouter Fusion is treated as a multi-model deliberation source, not as the durable project ledger.
  • LangGraph, AutoGen, and CrewAI are agent or workflow frameworks; CWO can govern work around them without claiming to be their runtime.
  • Claude Code, Gemini CLI, and Codex CLI remain coding-agent surfaces; CWO records which surface did what and whether the evidence was accepted.
  • Bring-your-own-subscription (BYOS) or bring-your-own-key (BYOK) access stays with the operator, provider account, local endpoint, or OpenRouter setup. CWO records approval and provenance; it does not broker credentials.
  • OpenShift AI vLLM is a local-worker option through an OpenAI-compatible profile, with evaluator and architect adjudication before findings become implementation work.
  • Beads provides the durable task graph, dependency state, closure rationale, evidence, residual risk, and follow-up brief for later agents.

Keep exact product claims in review packets and release notes tied to current vendor documentation. Public CWO copy should stay at the durable boundary: governance, provenance, Beads-backed memory, evaluation, and handoff.

Execution Profile Fit

Use cases become easier to size when the execution profile is explicit. CWO keeps the same Beads, evaluation, and adjudication controls while the shell and model endpoints change.

Small connected fix Connected single-operator Codex path; one Beads task is often enough.
High-risk plan review Connected Codex path with approved contractor packets, evaluator scoring, peer-review disposition, and architect adjudication.
Restricted shell OpenCode or manual operator envelope; no contractor sharing unless the environment policy permits it.
Airgapped local models Local Beads plus approved RHOAI/vLLM model profiles for review, worker, architecture, or synthesis candidates after benchmark gates.

Contractors, local workers, and synthesis lanes do not approve or merge work. They produce evidence that must pass the evaluator and be accepted by the architect.

Complex Use Cases

Use the complex pattern when a Codex architect plan is important enough to benefit from independent model critique before implementation. Codex still owns architecture, integration, validation, and release judgment.

  1. Ask for the prompt coach and approve third-party sharing before any packet is built.

  3. Record dispatch IDs, packet SHA values, return files, and evaluation decisions.
  4. Use ChatGPT Pro 5.5 Extended Reasoning only for the final plan bundle.

Acceptance Gates

Complex review output is evidence, not a merge decision. Codex evaluates returns, quarantines unsupported or boundary-breaking claims, turns accepted findings into follow-up work, validates the implementation, runs publish sanitization when public output is involved, and records the final durable work log.

For exact executor IDs, job labels, browser confirmation requirements, and helper commands, use the Reference page.
