Start a new conversation, then extend the program

Inspect your diff and handoff, then exit the first session using the client’s controls. Start a fresh named session in the same practice project; do not resume the earlier conversation. Use the same working launch command as the first session, including the explicit named-profile alternative if you used it. If you used a main-model override, keep that override too. Reuse the exact working command saved in HANDOFF.md instead of the default command below when they differ. Startup recovery covers the explicit launcher alternative.

Terminal

cd "$HOME/cwo-first-project"
cwo-codex -C "$HOME/cwo-first-project"

Prompt inside Codex

Use $complex-work-orchestration. Reconstruct this project’s state from README.md, HANDOFF.md, current files, and local Beads records. Identify the saved validation requirements and dependent CLI task. Verify the accepted validator tests before editing.

I authorize in-thread maintenance to add the CLI described in README.md. Preserve the validation contract. Add subprocess tests for valid input (exit 0), invalid configuration (exit 1), and file, JSON, and usage errors (exit 2).

Run validation and inspect the final diff. Accept and close the CLI task only after its checks pass; preserve the accepted validator task and its dependency. Update HANDOFF.md with the final result, actual checks, both task IDs and the next action (or completed scope with no successor). Identify any missing or uncertain state.

Use only the existing local Beads backend. No delegation, service-host contact, tool-initiated external network requests, commits, pushes, publication, or global configuration changes.

Expected: the new session finds the requirement that ports must be whole numbers, not boolean values, and reruns the validator tests before adding the CLI. Check the files and task records rather than accepting a claim that it remembers the earlier conversation:

Open a second terminal in the practice directory, or exit the finished client before these checks. Replace the two task placeholders with IDs from your handoff.

Terminal

cd "$HOME/cwo-first-project"
python3 -m unittest -v
python3 checker.py service.json
python3 checker.py invalid.json
echo $?

Expected: the valid file prints valid; invalid input prints an error and the last command prints 1. The agent’s subprocess tests must also cover exit 2 for a missing file. Inspect both task IDs from the handoff with bd show TASK_ID; the CLI must name the accepted validator as its prerequisite. If a task is missing, search with bd list --all. Recover missing information from files and tests, and mark anything you cannot verify.

Check the saved completion record

Terminal

cd "$HOME/cwo-first-project"
git diff cwo-tutorial-start -- checker.py test_checker.py
cat HANDOFF.md
bd show VALIDATOR_TASK_ID --json
bd show CLI_TASK_ID --json

Finish only when the tests pass, both tasks are accepted and closed, and the CLI still depends on the validator. Check that the diff preserves validation behavior and that the handoff describes the actual result. Ask the agent to fix an open task or stale handoff even if the utility works; do not weaken the accepted tests.

Inspect the result

You now have a command that reads a configuration file, reports whether it is valid and returns an exit status other tools can use. You also have tests and a project record explaining the requirements and completed tasks. The second session used those files and task records, not the earlier conversation. Keep them together when handing the project to another person or agent.
