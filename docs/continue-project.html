Leave, then continue from project state

Inspect your diff and handoff, then exit the first session using the client’s controls. Start a fresh named session in the same practice project; do not resume the earlier conversation. If you used a main-model override, reuse the exact working launch command saved in HANDOFF.md instead of the default command below. Startup recovery covers the explicit launcher alternative.

Long commands keep their original lines. If a line continues beyond the edge, scroll inside its code block; select the text to copy it.

Terminal

cd "$HOME/cwo-first-project"
cwo-codex -C "$HOME/cwo-first-project"

Prompt inside Codex

Use $complex-work-orchestration. Reconstruct this project’s state from README.md, HANDOFF.md, current files, and local Beads records. Identify the validator decision and dependent CLI task. Verify the accepted validator tests before editing.

I authorize in-thread maintenance to add the CLI described in README.md. Preserve the validation contract. Add subprocess tests for valid input (exit 0), invalid configuration (exit 1), and file, JSON, and usage errors (exit 2).

Run validation and inspect the final diff. Accept and close the CLI task only after its checks pass; preserve the accepted validator task and its dependency. Update HANDOFF.md with the final result, actual checks, both task IDs and the next action (or completed scope with no successor). Identify any missing or uncertain state.

Use only the existing local Beads backend. No delegation, service-host contact, tool-initiated external network requests, commits, pushes, publication, or global configuration changes.

Expected: the new session identifies the saved decision and reruns tests before implementing the CLI. A vague recollection of the old conversation is not the evidence. Check the resulting artifact:

Terminal

cd "$HOME/cwo-first-project"
python3 -m unittest -v
python3 checker.py service.json
python3 checker.py invalid.json
echo $?

Success: the valid file prints valid; invalid input prints a message and the last command prints 1. The agent's new subprocess tests must also cover exit 2. If continuation cannot locate the task, use bd list --all, then bd show TASK_ID with the actual ID from your handoff. Inspect both actual task IDs with bd show TASK_ID and confirm the CLI prerequisite names the accepted validator task. Reconstruct missing state from files/tests, explicitly mark uncertainty, and do not pretend hidden context survived.

Check the saved completion record

Open a second terminal in the practice directory, or exit the finished client before these checks. Replace the two task placeholders with IDs from your handoff.

Terminal

cd "$HOME/cwo-first-project"
git diff cwo-tutorial-start -- checker.py test_checker.py
cat HANDOFF.md
bd show VALIDATOR_TASK_ID --json
bd show CLI_TASK_ID --json

Finished when: current tests pass, both tasks are accepted and closed, the CLI still names the validator prerequisite, the diff preserves the validation contract, and the handoff matches the actual result and remaining work. An open CLI task or stale handoff is unfinished even when the utility works. Ask the agent to repair record discrepancies before finishing; do not weaken accepted tests.

Inspect the result

You now have a utility and a project record explaining its behavior, checks and completed dependencies. The next session used files and task records, not the earlier conversation. Keep them together when handing the project to another person or agent.
