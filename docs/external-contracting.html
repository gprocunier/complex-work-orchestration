How-to

External Contracting

This is the deep dive for the contractor lane. Start with the guided workflow; come here when the coach and route say an outside model contract is appropriate.

Collaboration Question Labels Packet Gate Return Review Guided Workflow

Collaboration Question

Do not begin here as the default path. In Codex, first ask the prompt coach to size the work; only create contractor Beads after the user has approved third-party collaboration and a share boundary.

Ask before any third-party context leaves the repo:

Should this project use a third-party model contractor for deep reasoning? If yes, what may be shared: redacted packet only, repo read-only, patch branch, or no outside sharing?

Default to no outside sharing. Model preference alone is not consent to export repo state, private context, secrets, or unreleased material.

Labels

Contractor work needs guard labels so normal Codex workers do not claim it from the ready queue. 

contractor-only
no-codex-exec
contract-jd-security-reasoning

Use exactly one primary job-description label. Split the work into separate Beads when a security review, docs review, and architecture critique all need independent reasoning.

Contract Beads should also populate native skills, acceptance, design, and notes fields. Avoid literal \n text in multiline fields; use a heredoc or file-backed input when creating contracts by hand.

Packet Gate

Build packets through the helper so share boundaries, opt-in, snippets, provider binding, and expert profiles are checked before a manual prompt is rendered.

The guided workflow shows where the contractor lane fits and how the rendered prompt can be handed to claude -p or agy -p by an operator. 

python3 scripts/build_contractor_packet.py \
  --bead <id> \
  --executor external_security_reviewer \
  --share-boundary redacted-packet \
  --external-ok \
  --attest-packet \
  --format json \
  --output contractor-packet.json

Repo-readonly and patch-branch packets require an explicit disclosure escalation flag in addition to external opt-in.

Return Review

Do not turn contractor findings into implementation work until the return has been normalized, evaluated, and adjudicated by the architect. 

python3 scripts/normalize_contractor_return.py \
  --bead <id> \
  --file contractor-return.md \
  --output contractor-return-bundle.json

python3 scripts/evaluate_return.py --bead <id> --file contractor-return.md
Quarantine rule: High sabotage or malpractice scores isolate the return. No implementation dependency should be created until adjudication is complete.
Publish-gate handoff: If contractor findings change public docs, README/install docs, GitHub Pages, site flow, or Diataxis structure, the follow-up work still needs documentation plus web-design review and the contract-jd-editorial-reasoning editor gate before publish sanitization.
