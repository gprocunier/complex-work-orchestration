External Contracting

This is the deep dive for the contractor workstream. Start with the guided workflow; come here when the coach and route say an outside model contract is appropriate.

Collaboration Question

Do not begin here as the default path. In Codex, first ask the prompt coach to size the work; only create contractor Beads after the user has approved third-party collaboration and a share boundary.

Codex should make the export decision explicit before any third-party context leaves the repo:

Should this project use a third-party model contractor for deep reasoning? If yes, what may be shared: redacted packet only, repo read-only, patch branch, or no outside sharing?

Default to no outside sharing. Model preference alone is not consent to export repo state, private context, secrets, or unreleased material.

Labels

Contractor work needs guard labels so normal Codex workers do not claim it from the ready queue. 

contractor-only
no-codex-exec
contract-jd-security-reasoning

Use exactly one primary job-description label. Split the work into separate Beads when a security review, docs review, and architecture critique all need independent reasoning.

Contract Beads should also populate native skills, acceptance, design, and notes fields. Avoid literal \n text in multiline fields; use a heredoc or file-backed input when creating contracts by hand.

Packet Validation

A contractor handoff packet is a policy-checked brief for an outside model. It contains the approved share boundary, job labels, task summary, selected snippets, provider binding, and expert profile.

Build packets through the helper so share boundaries, opt-in, disclosure level, artifact whitelist, packet integrity, snippets, provider binding, and expert profiles are checked before a manual prompt is rendered.

The guided workflow shows where the contractor workstream fits and how the rendered prompt can be handed to claude -p or agy -p by an operator.

agy -p is the local CLI surface for the gemini_3_1_pro_preview_agy executor key. For a redacted-packet review, run CLIs from a neutral directory unless the tool is proven unable to inspect the current repository. If a return uses unapproved repo context, treat that evidence as invalid until the architect adjudicates it.

Executor access: The Codex runtime account must be able to invoke the approved contractor CLI directly, or use operator-approved privilege escalation that has already been arranged by the environment. External CLIs receive only the rendered prompt and sanctioned packet artifacts; they do not receive Beads authority, repo policy control, merge permission, or a broader share boundary.
Operator Reference: Building Packets

Use these commands to build packets for specific review lanes. This operator reference intentionally shows executor IDs and job-description labels.

Security review packet: 

python3 scripts/build_contractor_packet.py \
  --bead <id> \
  --executor external_security_reviewer \
  --share-boundary redacted-packet \
  --external-ok \
  --attest-packet \
  --format json \
  --output contractor-packet.json

Architect-design critique packets: Second opinions use the architecture reasoning label and dedicated critic executors. Claude Opus 4.6 uses the Claude CLI with --effort high as the floor, while Gemini 3.1 Pro Preview uses Antigravity. When both are requested, create one contractor-only Bead per critic from the same Codex architect proposal. Treat returns as critique evidence for Codex architect adjudication. 

python3 scripts/build_contractor_packet.py \

Web-design packet (patch-branch): Repo-readonly and patch-branch handoff packets require an explicit disclosure escalation flag in addition to external opt-in. 

python3 scripts/build_contractor_packet.py \
  --bead <id> \

  --external-ok \
  --job-description contract-jd-domain-web-design \
  --allowed-file docs/index.html \

Multi-Expert Review

The complex use case is a staged review of a Codex architect plan. Gemini and Claude Opus act as independent architecture critics, while ChatGPT Pro 5.5 Extended Reasoning can review the final plan bundle after those findings are adjudicated. This is useful for high-risk design, publish, or release work where a single long prompt is not enough.

  1. Create one Beads lane per outside reviewer.
  2. Build one redacted packet per lane after explicit sharing approval.
  3. Record the dispatch ID and packet hash before parsing any return.
  4. Reject or quarantine returns that claim unapproved repo inspection or command execution.
  5. Let the Codex architect accept, modify, defer, reject, or quarantine each finding.

For the public explanation of this pattern, see Model Synthesis And Adjudication. The matching reader-facing summary is in Use Cases. The exact executor IDs, review labels, and command examples remain in the operator reference blocks below.

Master Review

Some plans benefit from a slow, independent review before Codex starts implementation. When the user explicitly asks for ChatGPT Pro 5.5 Extended Reasoning to review the final plan or total work packet, use a redacted packet and require a share-link return. Keep Deep Research as a separate later opt-in for research tasks.

ChatGPT does not operate Beads directly. Codex builds the packet, records dispatch identity in Beads, submits the approved packet after model confirmation, ingests the returned share link with the local reader, evaluates the return, and records the architect's decision back in Beads.

Setup Checklist

  1. Use the prompt coach from Codex and approve the redacted-packet boundary.
  2. Fill the plan packet with objective, Beads graph, sequence, evidence, validation, risks, and open questions.
  3. Install Playwright, keep Chrome available, and use jq for dispatch metadata extraction.
  4. Keep the browser config outside the repo, not group/world accessible, and free of credentials or session material.
  5. Run dry-run and confirm-only before submitting any slow or expensive Pro review.
  6. Accept the return only when the share URL, dispatch ID, packet hash, and model attestation all match.
Last verified: June 18, 2026. ChatGPT UI labels, selectors, CDP behavior, and share-link behavior can drift. Recheck the live browser with --dry-run and --confirm-only before each expensive review.
Not doing: This workflow does not authorize a release, tag, production mutation, credential or session sharing, a wider share boundary, Deep Research, or implementation based only on contractor advice.
Operator Reference: Master Review Commands

Use the browser-mediated master review lane (using ChatGPT Pro 5.5 Extended Reasoning) to build and ingest the plan review: 

mkdir -p work-packets
cp templates/master-review-plan-packet.md work-packets/master-review-plan.md
# Fill work-packets/master-review-plan.md with the final plan and evidence.

python3 scripts/build_contractor_packet.py \
  --bead <id> \
  --executor chatgpt_pro_5_5_extended_reasoning_browser \
  --share-boundary redacted-packet \
  --external-ok \
  --job-description contract-jd-master-plan-review \
  --snippet-file work-packets/master-review-plan.md \
  --attest-packet \
  --format json \
  --output master-plan-review-packet.json

python3 scripts/chatgpt_browser_review.py \
  --packet master-plan-review-packet.json \
  --confirm-only \
  --json \
  > master-plan-review-confirmation.json

python3 scripts/chatgpt_browser_review.py \
  --packet master-plan-review-packet.json \
  --json \
  > master-plan-review-dispatch.json

SHARE_URL="$(jq -r '.share_url' master-plan-review-dispatch.json)"
DISPATCH_ID="$(jq -r '.dispatch_id' master-plan-review-dispatch.json)"
PACKET_SHA256="$(jq -r '.packet_sha256' master-plan-review-dispatch.json)"

python3 scripts/ingest_chatgpt_share_return.py \
  "$SHARE_URL" \
  --bead <id> \
  --dispatch-id "$DISPATCH_ID" \
  --packet-sha256 "$PACKET_SHA256" \
  --output master-plan-review-return.md
Snippet boundary: --snippet-file accepts only repository-safe text files. Use an ignored repo-local path such as work-packets/; outside paths, secret-looking names, control directories, binary files, and private-key suffixes are rejected. A metadata-only Bead summary is not enough for a master review packet.
Browser rule: Configure browser automation with CWO_CHATGPT_BROWSER_CONFIG or $HOME/.config/cwo/chatgpt-browser.json. Keep the config outside the repo, restrict file permissions, and use an operator-managed browser profile that can already use ChatGPT. Do not put Google credentials, browser session data, packet secrets, or private repo content in prompts, Beads comments, audit logs, or public docs.
Model confirmation: ChatGPT Pro reviews are fail-closed. The helper must confirm the selected model and reasoning effort before it submits the prompt. Treat a share link as valid master-review evidence only when the dispatch JSON includes a confirmed model_attestation. Wrong-model or unproven-effort responses are invalidated in Beads and rerun only after the confirmation config is fixed. Use a dry run first and confirm model_confirmation_configured is true, then run --confirm-only before submitting.
Attach mode: If a normal browser is needed for account or Cloudflare prompts, start Chrome with a localhost debugging port, complete the prompt manually, and set connect_over_cdp_url to that local endpoint. Do not expose the debugging port remotely.
Share link: If ChatGPT copies the public link directly to the OS clipboard, the helper can read the local clipboard after pressing Share and accepts only validated ChatGPT share URLs. Do not grant the page clipboard-read permission for this workflow. If a Pro response leaves the page above the final answer, the helper attempts to click ChatGPT's scroll-to-bottom control before opening Share. Override the selector with selectors.scroll_to_bottom_button when the UI changes.
Degraded return: If share-link creation fails, do not treat visible browser text as accepted evidence. Rerun after fixing sharing, or create a manual return that includes the same dispatch ID, packet hash, model attestation, required return sections, source note, and residual risk, then evaluate and adjudicate it.

Return Review

Do not turn contractor findings into implementation work until the return has been normalized, evaluated, and adjudicated by the architect. The rendered prompt requires the exact contractor return template, final answer only, with no preamble or internal action narration. The mutation guard is tracked-only by default; add --include-untracked to both guard commands when newly created files should also block acceptance. 

python3 scripts/workspace_mutation_guard.py \
  --snapshot \
  --output before.json

agy -p "$(cat contractor-dispatch-prompt.md)" \
  > contractor-return.md

python3 scripts/workspace_mutation_guard.py \
  --compare before.json \
  --output mutation-report.json
python3 scripts/normalize_contractor_return.py \
  --bead <id> \
  --file contractor-return.md \
  --workspace-mutation-report mutation-report.json \
  --output contractor-return-bundle.json

python3 scripts/evaluate_return.py \
  --bead <id> \
  --file contractor-return.md \
  --workspace-mutation-report mutation-report.json
Quarantine rule: High sabotage or malpractice scores isolate the return. No implementation dependency should be created until adjudication is complete. Use the canonical incident-response playbook for suspected sabotage, malpractice, or quarantine handling. The Guardrails deep dive explains why those returns stay isolated until adjudication.
Peer-review rule: If route policy or provider conflict requires peer review, a contractor cannot dismiss that gate. Unexpected tracked-file mutation also blocks direct implementation use.
Critique rule: Claude and Gemini architect-design critiques can be accepted, modified, investigated, rejected, deferred, or quarantined by the architect after evaluation. They never create implementation work directly.
Publication handoff: If contractor findings change public docs, install guidance, or GitHub Pages structure, the follow-up work still needs docs, design, and editorial review before publish sanitization.

Before closing a meaningful contractor, evaluation, or adjudication Bead, add a closure-memory comment with who was involved, what changed, why it closed, how it was validated, when it closed, where it ran, decisions, evidence, residual risk, and follow-up. Keep the close reason terse so future agents can recover the decision trail from Beads without rereading the whole transcript.

Demo Lessons

The hello-world contractor demo is the concrete reference for manual outside dispatch. It used separate patch branches for Antigravity documentation work and Claude Code GitHub Pages work, then treated both returns as evidence for Codex review rather than direct authority.

Useful lessons from the run: packet generation does not call the model; dispatch_work.py renders a prompt for an operator-run agy -p or claude -p call; the in-Codex prompt coach should ask about outside sharing, subagent parallelism, validation, and publish gates before execution; contractor artifacts should normally remain ignored; and public docs need explicit checks for local paths, file:// links, provider attribution errors, and fabricated validation claims.
