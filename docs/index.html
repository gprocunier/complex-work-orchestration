Two-minute version

The first-class interface is the Codex conversation.

Ask Codex to use the skill and coach the prompt. Codex runs the local helper, asks the decisions that change execution, creates a durable Beads task graph when needed, and records validation evidence before the work is accepted or published.

A Beads task graph is the durable ledger of tasks, dependencies, evidence, and handoff state. A review worker is a bounded subagent that gathers evidence; the main Codex thread still owns integration and final judgment. A contractor handoff packet is a policy-checked brief for outside or local model review.

CWO complements model and agent tools; it does not replace OpenRouter Fusion, LangGraph, AutoGen, CrewAI, Claude Code, Gemini CLI, or Codex CLI. It records which tool or model was used, which BYOS, BYOK, or local endpoint boundary applied, and which evidence was accepted into the Beads work graph.

    Invoke from Codex

  2. 2

    Coach and route

    Let Codex run the coach and policy route, then answer only the choices that change execution.

  3. 3

    Record Beads

    Create an epic or task graph with clear scope, dependencies, evidence, and handoff notes.

  4. 4

    Validate before accepting

    Use the selected validation gates before accepting findings, contractor returns, or publication work.

Explanation

Why the harness separates roles

Complex work fails when planning, execution, validation, and final judgment collapse into one hidden thread. This skill keeps the main Codex thread as architect, records durable state in Beads, assigns bounded work to internal review workers, and treats outside or local models as evidence sources rather than implementation authority.

The full explanation covers durable memory, contractor boundaries, publication quality, and the failure modes the harness is designed to avoid.
