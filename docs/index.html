Complex Work Orchestration

Turn large, risky, or multi-agent work into a durable operating model with architect judgment, project-manager coordination, bounded workers, optional outside model contracts, and validation evidence.

Two-minute version

Use the skill when work needs memory, roles, or release judgment.

The skill helps Codex decide whether to stay in-thread, create a lightweight Beads task, or scaffold a full architect/PM/worker harness. It is especially useful when work spans sessions, repositories, outside model reviewers, or publication gates.

Beads is the durable state layer. Outside contractors and local workers are treated as bounded evidence sources; the main thread remains the final decision owner.

Operating flow

Everything starts with sizing the work before dispatching it.

  1. 1

    Coach the prompt

    Use scripts/coach_prompt.py to choose the right harness level and validation bar.

  2. 2

    Route the work

    Use policy-backed routing to select experts, risk level, share boundary, and executor fit.

  3. 3

    Record Beads

    Create an epic or task graph with clear scope, dependencies, evidence, and handoff notes.

  4. 4

    Validate before accepting

    Run tests, repository validation, packet checks, return evaluation, and publish-sanitization gates.

Explanation

Why the harness separates roles

Complex work fails when planning, execution, validation, and final judgment collapse into one hidden thread. This skill keeps the main Codex thread as architect, records durable state in Beads, assigns bounded work to workerbees, and treats outside or local models as evidence sources rather than implementation authority.

The result is slower than a single prompt for tiny tasks, but much safer for publication, multi-session work, contractor review, and high-risk integration decisions.
